证券交易、借贷、医疗等不进入本包执行范围是明确边界；业务成果的复制与积累可以单独讨论，不能把所有“杠杆、复利”都视作金融话题。

免费共创卡确有从一对一实践提炼共性再转一对多的阶段。这是一种起步办法。用户已排除持续定制服务时，应尊重其约束，选择有限的产品试用与固定支持范围，不能将一对一服务当成普遍必经生意。

## 必要修复范围

以下是本次审查提出的修复设计，尚未写入已安装skill；不冒充作者统一步骤。

1. 主入口加入“方向需匹配收入结构”的判断，并为“不想卖工时、想做可反复销售产品、杠杆、复利”等意图提供明确路由。不能只藏在归档资料。
2. 在机会匹配与项目筛查中增加：每次留下什么资产、下一次如何复用、新增一个用户需多少额外工作、由谁控制和允许使用这些成果、什么积累会改善后续产品或触达。真实未知仍保留；不设置虚构评分。
3. 补齐复利三步的跨卡连接：可使用的成果样机→公开解决过程→取得真实反馈→更新同一资产→下一次复用。支持从已有阶段进入，避免每次从零做整套流程。
4. 将“资产”和“用户/信任/渠道的积累”分开记录。模板和代码只是候选资产；持续有人使用、交付成本、维护与触达都需观察。
5. 加入技能组合检查，允许设计、编程、营销共同形成一个产品的解决能力；保留真实成果核查，不能因多学历或经历就宣布商业优势。
6. 补充词汇与测试，重新核对引用后按原构建流程更新。现有包为生成产物，直接手改入口会造成版本分叉；本次仅给审查与修复合同。

## 最少必要的筛选框架

这套框架用于修复当前缺口，是对已定位来源的审查综合：

| 要检查什么 | 需要留下的证据 | 仍未知时的处理 |
|---|---|---|
| 具体人需要什么结果 | 实际任务、已有办法、卡点 | 收集具体问题，不先扩大制作 |
| 能否做一次并多次使用/销售 | 最小可用版本、另一份输入或另一个人的使用 | 做小样与换输入检查 |
| 每增加一个用户，工作如何增加 | 实际操作、支持、返工、接口及维护成本 | 保留空项，先记录，不能声称零成本 |
| 做完留下什么由自己控制的东西 | 原创成果、版本、来源与使用条件 | 明确第三方依赖与许可，不能将全部供给算自有资产 |
| 每次行动怎样使下一次受益 | 改良模板/代码、同类问题记录、可信展示、用户反馈与自愿推荐 | 指定一个积累机制及观察节点 |
| 小试是否能承受并退出 | 时间/钱上限、结果节点、继续/调整/停止条件 | 先缩小到可恢复动作 |

重复执行可以提高熟练度；同一成果服务更多人可以放大产出；新反馈、版本、知识与信任持续改善后续工作可以形成业务积累。这些分别检查，不因“能复制文件”就宣布已经复利。

应用于本次用户：月收入目标1000～2000元不能覆盖其“脱离逐单定制”的约束；候选产品必须同时说明实际问题、固定可复用交付、每单新增工作和积累机制。当前尚未选定通过这些条件的商品，也没有本轮真实订单。
